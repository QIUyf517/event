## 实现范围

- 证据整理 Agent 在阶段三取得的文档范围内选择重点片段，调用模型提取事件事实；Python 检查对象、窗口、逐字引用、数字字面值、发生日期和费用上限。
- 独立 SQLite 图谱库保存来源、片段引用、事实主张、事件、冲突及跨来源关系。来源资料库只读；相同研究运行覆盖同一图谱记录。
- 相同期间的财务披露合并展示，银行业务与集团数据分开。跨来源数字按单位和显示精度比较；转载、支持及矛盾关系保留。日期缺少完整原文依据时标记未知。
- React 时间线展示事件、来源、原文、系统提取的主张、数字核查状态及冲突。生成操作需要 API 密钥，读取已保存结果不调用模型。

入口：`POST /api/v1/event-research/timeline/build`、`GET /api/v1/event-research/timeline` 和 `GET /api/v1/event-research/timeline/{run_id}`。验收脚本：`python -m scripts.accept_event_research_phase4`；已保存模型结果可用 `--resume --reprocess-saved-extraction` 只重算确定性逻辑，不再次调用模型。

## 未通过完整真实资料验收的原因

1. 这 9 个真实样本事件都没有可由所引用片段**直接确认的完整发生日期**，因此真实页面的事件均在“日期待确认”组；按已知发生日排序只由合成用例证明。资料发布日期单独保留，不能冒充事件发生日。
2. 固定快照没有独立公告，且每份文档最多选两个片段、每次最多提取 12 条事实；不能据此证明重要事件无遗漏或三家公司资料覆盖完整。
3. 茅台报道的二季度净利润算式不一致尚未通过独立来源解释。`partial` 是符合证据的输出，不能写成已核实的季度利润。
4. 人工检查覆盖了三家公司保留事件的主要数值、业务归属和异常项，未对所有未入选片段、所有模型措辞和页面各浏览器状态逐条审核。逐字引用、结构测试及 `extracted` 状态都不能替代全面语义验收。

下一验收门槛是补充可独立核对的公告和明确发生日期的原文样本，对遗漏事件、数字口径与界面展开状态做逐条人工标注；之后再运行同一验收脚本。阶段五的竞争性假设、反方核验与因果表述不属于本阶段已交付能力。
