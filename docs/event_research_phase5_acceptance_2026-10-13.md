## 已实现

- `app/models/event_research.py` 增加有图谱运行 ID、候选解释、反方检索、核验发现、结论等级和来源库哈希的报告契约。引用 ID 必须属于嵌入的当前图谱，候选解释最多三个。
- `app/agents/hypothesis_debate.py` 用至多四次有界模型调用生成候选解释、反方检索词、核验意见和报告草稿；只读查找保存的原文与行情。程序重新核对原文位置、快照哈希、来源日期、事件动作日期、数值冲突、转载依赖、缺失证据及反方结果。模型或预算失败时保留已有结果并降级。模型草稿只存档，不作为对外结论。
- `app/data/repositories/event_debate.py` 在独立 SQLite 库保存报告。API 增加带 `X-API-Key` 的 `POST /api/v1/event-research/debate/build` 和只读的 `GET /api/v1/event-research/debate`、`GET /api/v1/event-research/debate/{run_id}`。公开响应省略未经核验的模型草稿和本机快照路径。
- 阶段四图谱提取增加公告遗漏警告，并要求发生日期附近有事件动作依据；公告落款日、统计截止日和未来计划日不能直接当作已发生日期。企业动作按动作属性归组，避免把缴款数量与股份登记日期合成一个事件。

## 自动验收与剩余门槛

项目 `.venv` 的 Python `pytest -q` 为 **42 passed**。React `npm test -- --run` 为 **3 passed**，`npm run build` 通过。API 测试使用独立临时数据库和模拟模型，覆盖无密钥被拒绝、持密钥写入以及只读查询；它不证明真实 HTTP 服务的模型调用稳定性。真实模型已通过验收脚本执行，但三例全部为 `partial`，并非研究正确率样本。

逐条人工阅读全部 616 个切片并非原路线图规定的硬性验收条件；这里缺少的是针对入选重要事件和报告关键事实的可审计复核记录。因此，**第五阶段暂不能标为完整验收通过，也不能在 README 或简历中写成已证实的企业事件因果分析能力。**
