# 企业事件研究阶段三边界处理记录

日期：2026-10-12。此记录仅说明阶段三开始前已处理的两处边界，**不是阶段三验收通过记录**。

## 1. ETF 固定路径与企业事件流程分开

- `app/agents/llm_research.py` 保留 ETF 研究用途。
- 新增 `app/agents/event_orchestrator.py`：模型只规划任务图；Python 校验主体、30天窗口、工具白名单、步骤数、依赖与 Token 用量，再按依赖执行本地只读资料工具。节点可以并行，失败时保留其他节点取得的原文片段并返回部分状态。
- `POST /api/v1/event-research/plan-run` 需要 API 写入密钥，以限制会产生模型费用的调用。返回计划、原文片段、轨迹和停止原因；不生成事件时间线、因果判断或投资建议。
- 当前只用假模型完成本地测试，未调用真实模型。模型服务费用无法仅凭 Token 数准确计算；费用上限和真实模型运行仍需后续验收。公司行情工具也尚未接入。

## 2. 合成基准与真实快照分开

- 原20道题仍是人工合成的回答基准。真实快照不能直接用于这20题的标准答案评分。
- `evals/event_research_real_snapshot_cases.json` 单列三道真实样本资料核对题，使用2026-08-14至2026-09-13窗口，每家公司要求一份财务披露和一篇新闻。
- `python -m scripts.audit_event_suites` 只读验收快照。结果为：合成基准20题仅有标注、未运行答案评分；三道真实样本题的六个指定来源均有原文切片并可通过检索取出。两个回答分数均为空，且不产生合并分数。

## 验证

- `python -m pytest -q`：123 passed in 10.68s。完整测试在受限沙箱外执行；测试使用临时 SQLite 和假模型。
- `python -m scripts.audit_event_suites`：真实样本三题均为 `retrieval_ready`；没有联网或写入样本库。
- 这些结果证明代码边界和样本可检索性，不证明模型规划在真实服务上的稳定性，也不证明语义解释正确。
