# AI 协作研究阶段验收记录（2026-10-10）

## 已实现

- 网页和 CLI 新增显式选择的 AI 协作研究；打开网页、切换选项均不调用模型，点击生成后才调用。
- 模型提出研究计划，数据与资料角色按有上限的工具循环取证；程序限定基金、日期、可读工具与主题范围。规划遗漏明确主题时由程序补齐，增加未询问主题时由程序删除，并记录调整。
- `get_signal` 的五项指标由 Python 计算；`search_documents` 和 `get_document_chunk` 只读本地资料。程序先生成可核验答案，模型复核并推荐逐字摘录；摘录须有有效编号且能在片段中连续定位。模型核验失败时降级，不发布 AI 结论。
- 资料检索正文优先于标题，同一文档最多占两个结果；模型检索为空时，按基金代码读取少量背景片段并在报告中标注。背景资料不能证明行情或份额变化成因。
- 工具调用、执行轨迹、模型用量与报告存入当前模式的本地库；真实数据的收集仍由用户在网页手动触发。

## 真实来源与数据库

三份新增资料来自上交所：[510300 简称变更公告](https://www.sse.com.cn/disclosure/fund/announcement/c/new/2026-01-08/510300_20260108_0DLV.pdf)、[510050 IOPV 计算机构调整公告](https://www.sse.com.cn/disclosure/fund/announcement/c/new/2026-02-09/510050_20260209_O593.pdf)、[510500 期权合约调整公告](https://www.sse.com.cn/assortment/options/disclo/update/c/c_20260714_10825473.shtml)。导入前先联网解析全部正文并核对基金代码，随后用 SQLite backup API 备份原库，再一次性写入。导入前备份 `data/etf_research.live.before-ai-docs-20261010-173707.sqlite3` 为 3 份文档、3 个片段；导入后现库为 6 份文档、13 个片段。两库 `PRAGMA integrity_check` 均为 `ok`。本次导入没有同步行情或份额。

2026-10-10 只读核查现库各来源截止日期：

| 510300 | 2026-10-09 | 2026-10-09 |
| 510050 | 2026-10-09 | 2026-09-30 |

## 运行与质量证据

- 项目 `.venv` 全量测试：`92 passed`。
- 真实 DeepSeek 接口在临时演示库中完成规划、数据取证、资料检索、程序核验、模型核验五步；未写真实库。
- 真实数据只读快照试跑：510300 在查询日 2026-10-10 返回 `answered`，行情和份额均截至 2026-10-09，命中两个资料片段，五个角色均成功；报告逐字摘录了简称变更公告 [D1]。原库未写入。这个结果证明该单例流程能运行，不能证明其他 ETF 或所有提问的质量。
- 三个手写演示场景的最终对照保存在 `output/semantic_comparison.json`（本机产物，不入 Git）：规则路径和多 Agent 路径各 3/3 通过自动字段检查；单模型路径两次把结构化信号写为 `neutral`、一次引用不存在的 `D1`。多 Agent 每题耗时 2.2–3.9 秒、消耗 1,313–2,727 token；规则路径约 18–31 毫秒。时间和 token 是这一次运行记录，不是稳定性能指标。
- 人工抽查了上述三份多 Agent 直接回答：510300 信号及来源日期与程序输出一致，演示资料被明确标记为合成；510500 收盘价 5.7342 元、份额 151,020,000,000 份、近五个可用披露日变化约 +0.96% 与程序结果一致；510050 份额 106,020,000,000 份、变化约 +1.38%，明确说明现有资料不能证明成因。仅抽查三份回答，不代表全量语义正确。

## 尚未通过的边界

- 自动评测主要查结构、数值、日期和引用编号，不能证明摘录与用户问题的语义相关性；人工审核样本也只有三份。
- 单模型对照使用同一组已入库证据，但输出结构与多 Agent 不完全相同；这是小样本诊断，不能据此宣称多 Agent 普遍优于单模型。
- 资料库仍很小，真实行情来源的持续可用性、全部基金份额新鲜度、多用户并发、模型费用上限和更大规模人工评测尚未验收。
- AI 只使用本地已入库资料；它不会自动上网寻找新公告，也不会自动收集行情。资料引用证明原文出现过，不能证明资金行为的因果解释。

## 12题方法对照补充验收

在固定的 `2026-09-30` 合成演示快照上，将手写场景从3题扩展为12题，覆盖数字事实、资料引用、综合研究和能力边界。三种方法均完成12题，共生成36份结果，没有接口运行错误。正式复跑的自动检查结果为：

| 方法 | 完全通过题数 | 检查项通过率 | 平均耗时 | Token合计 |
| --- | ---: | ---: | ---: | ---: |
| 规则流程 | 12/12 | 100.0% | 15.6 ms | 0 |
| 单模型 | 0/12 | 85.1% | 1152.5 ms | 9,784 |
| 多 Agent | 12/12 | 100.0% | 2817.2 ms | 20,253 |

首轮运行暴露两项评测设计问题：禁止词会把“不代表真实公告”误判为违规，能力边界题会因报告内部保留的计算字段被扣分；已离线修正规则，没有再次调用模型。首轮还发现单模型提示词示例会诱导固定输出 `neutral` 和无依据的 `D1`，因此保留首轮结果作为诊断记录，修正提示词后重新执行正式对照。多 Agent 首轮对“政策资料”错误回退到定期报告；程序现已把问题识别出的资料类型约束传入模型检索和回退检索，并加入回归测试，正式复跑正确返回“未找到政策资料”。

人工阅读了正式复跑的12份多 Agent 直接回答：数字、单位和日期与程序结果一致；三道资料题中的引用均能在对应合成片段中定位；份额变化没有被写成资金净流入；因果问题明确说明资料不能证明成因；预测和买卖建议题均拒绝作答。单模型多数答案包含正确数字，但经常把有完整数据的问题标为 `partial`，一次返回非约定状态 `ok`，并存在日期或边界措辞缺失，因此“0/12”表示没有一题通过全部严格检查，不代表12题内容全部错误。

这仍是一次固定合成快照上的小样本单次运行。多 Agent 的最终数字与主要回答由程序核验门生成，因此结果证明的是“模型规划与工具调用受到程序约束后，输出契约更稳定”，不能据此宣称多 Agent 的自由生成能力普遍优于单模型。模型耗时和 Token 也只是本次记录；尚未进行多次重复、置信区间、真实数据12题复验或更大规模人工标注。
