## 工程交付

- React 默认入口 `/research`：问题、计划与并行取证、时间线、候选证据组合、反方核验、程序报告。保留时间线和资料检索入口。
- `POST /api/v1/event-research/runs` 鉴权后返回202；后台仅执行本次用户请求。`GET /runs/{run_id}` 读取持久化阶段状态，不触发模型。URL携带运行ID，刷新后继续读取。
- 独立 `.runs.sqlite3` 保存完成阶段、工具执行起止时间、来源、Token、费用估算、耗时与停止原因；失败保留已完成阶段。服务启动将未完成任务标为中断，不自动续费。当前支持单进程运行，不是分布式任务队列。
- 原文抽屉分别标出原文、模型提取和程序检查；发生日期未知与数值冲突保持可见。引用关系有效不代表支持关系或因果成立。
- 旧报告读取接口与新研究接口统一使用 `public_debate`：不发布模型解释、反方叙述及自由文本结论。对外仅保留模型选择的证据ID、待核查类别及固定保守文字。内部原始记录仍保留供审核。**这限制了公开输出，并未修复或证明原始模型草稿正确。**
- `SingleEventAgent` 在同一图谱上运行一次候选生成，不运行独立反方、反证检索或报告模型；`compare_event_agents.py` 可与完整假设流程对照。它仅隔离假设阶段，不是端到端基线。
- `data/event_demo.json` 保存三家公司的历史公开投影；演示不包含完整来源库、规划轨迹或当时耗时。缺失字段不重建。演示模式禁止全部模型写入接口。

## 可重复运行

安装 Python 依赖后，一条命令构建React并启动只读历史演示（首次安装前端依赖需要网络）：

```powershell
.\.venv\Scripts\python.exe scripts/start_event_demo.py
```

打开 `http://127.0.0.1:8000/research`，选择三家公司之一；API健康检查为 `/health`。端口冲突时用 `--port 8006`。已构建可加 `--skip-build`。该脚本只写 `output/event-phase6-demo`，不改活动资料库和 `.env`。

正式研究仍使用常规 uvicorn 启动命令、独立真实来源库和已配置模型。前端已构建时由API同源提供，不需要另启Vite。Dockerfile也增加了前端构建阶段，本次未执行Docker镜像构建。

合成实验命令：

```powershell
.\.venv\Scripts\python.exe scripts/evaluate_event_phase6.py --output output/new-phase6-eval --repeats 2 --budget-usd 0.5 --live
```

不加 `--live` 只运行规则退化基线。输出目录必须不存在。模型实验显式启用当前配置的模型；密钥不进入记录。全局费用检查使用配置单价估算，不保证计入服务商未返回用量的失败调用。

真实图谱假设阶段对照命令（需允许向模型服务发送相关公开资料；本次运行已获用户明确授权）：

```powershell

```

## 已执行的20题实验

数据为阶段一的20道人工合成场景摘要。输入只含问题、场景记录、日期边界、工具名称与所有题共享的事件标签词表；不含逐题标准答案、期望事件、禁用短语或评分要点。两道未来信息题有显式分版本记录，程序在发送模型前过滤未来记录。其余场景只有摘要，没有原文级发布时间，不能借此验证真实文档时间隔离。

`rules` 只返回“无法进行开放研究”，不是有竞争力的规则研究系统。`single` 一次模型起草；`multi` 同模型起草、反方审查、修订三次调用。这是提示词角色消融，不是生产取证编排评测，不能把所选工具相关性称为实际工具调用正确率。

执行模型：`deepseek-v4-flash`。计划120次运行：规则40/40完成，single 39/40，multi 39/40；两次失败均记录为TLS连接中断，没有伪装成答案。无自动重试。已返回用量的估算费用合计 **0.1076823美元**；单价沿用仓库配置，仅为估算。

不同方法失败题不同，直接比较各自39条会有偏差。以下只对共同成功的**38对**结果取逐次宏平均；没有期望事件的题不计入事件覆盖均值，没有断言的题不计入断言率均值。

| 自动代理指标 | single | multi |
| --- | ---: | ---: |
| 所选工具相关性 | 94.74% | 97.37% |
| 引文逐字匹配率 | 98.68% | 99.12% |
| 事件标签覆盖率 | 71.57% | 67.65% |
| 无有效引文的断言率 | 1.32% | 0.88% |
| 评分要点词组覆盖率 | 93.20% | 91.89% |
| 平均耗时 | 3.52秒 | 7.42秒 |
| 38次费用估算合计 | $0.02835 | $0.07561 |

无效或未来记录引用计数为0，但它只检查引用ID，不证明所有自由文本无未来信息泄漏。引文逐字匹配不证明主张忠实；无有效引文断言率也不是语义幻觉率。禁止短语扫描无法识别否定语境。仅两轮样本，未做显著性推断。

**观察结果：多角色逐字引用指标略好，但事件覆盖与要点覆盖更低、耗时和费用更高；没有整体更优的证据。**

## 固定真实图谱的假设阶段对照

2026-10-23获得用户对三家公司已保存公开公告、新闻引文及派生图谱的外部模型发送授权后，按上面命令运行。三家公司各重复两轮，单Agent与多Agent各6次，共12次。双方使用**完全相同的已保存事件图谱**，只比较假设生成及独立反方核验环节；工具选择、事件覆盖和图谱引文质量均由共享上游决定，不能计为多Agent带来的改进。

来源SQLite在运行前后的SHA-256均为 `c7d3621343756af4f895831417771f40df4521bb79f472f033d67d00c49bcfe5`，与阶段四、五固定样本一致。图谱包含三家公司31个事件和84条引文；本次未采集新资料。十二次输出文件的SHA-256已按汇总索引逐一核对。费用估算合计 **0.0521613美元**，低于0.5美元预算。

第二轮中芯国际多Agent运行仅完成一次模型调用，模型返回的候选数量无效，质量门记录 `候选解释数量无效` 后降级为 `insufficient_evidence`。这次失败包含在表中，没有筛掉。候选或反方条数不代表内容正确；`partial` 也只是单次报告状态。费用和耗时更高是可测量结果，**研究结论质量是否改善尚不能判断**。

初步抽查原始草稿又发现日期性质风险，说明先前的语义问题尚未解决。例如 `688981-single-1.json` 提议把“报告资料库发布日期”作为“披露确认日”；图谱中的披露动作日却保留为未知。`688981-multi-1.json` 把“出资款截至8月14日缴纳完毕”与验资、登记、收证一并列入“有明确日期的动作”，容易把截止日算作完成日。这两条文件的SHA-256分别为 `a329354accc4da421a10d0b5c832368bdfc6ac2ddbb625c5d359ab1ff1020abc` 和 `16c947cb87c76a4a7932f9f10a8942ea9465d275959f795396904f9c6444e240`。这是问题线索，不替代12份草稿的完整人工审核；公开API只显示证据组合和程序保守文字，不发布这些原始陈述。

记录：`evals/event_phase6_real_compare_20261023.json` 保存每次运行的状态、用量、耗时、费用、输出文件哈希及汇总；`evals/event_phase6_real_human_review_20261023.json` 的12条语义审核仍均为pending。本机逐次原始草稿和程序公开投影在 `output/event-phase6-20261023-real-compare/`，原始草稿不对外发布。

可移交、可检查的实验文件：

- `evals/event_phase6_results_20261023.json`：120条运行索引、状态、分数、哈希、汇总及配对比较。
- `evals/event_phase6_runs_20261023.json`：每次运行原始JSON字符串，保留输入、答案、请求与回复。按UTF-8编码计算SHA-256可对应索引。
- `evals/event_phase6_human_review_20261023.json`：120条逐次审核记录，审核人和语义判定均为空、状态均为pending。它是**待审记录，不是已审核记录**。
- 本机 `output/event-phase6-20261023-eval-live/`：逐次JSON、汇总与审核表。初次关闭模型以及受沙箱网络限制的两次失败尝试分别保存在 `...-eval` 与 `...-eval-v2`，没有合并进最终指标。

合成题人工审核可使用 `scripts/review_event_phase6.py --reviewer "审核人姓名"`。脚本逐次并列显示输入、保存答案、人工标准、禁止结论和机器指标，人工键入 `pass`、`fail` 或 `uncertain` 及原因；每条决定即时保存到 `output/event-phase6-human-review.json`，下次运行可续审。没有人工输入时脚本不会自动签发结果。真实图谱逐次结果需参照本机 `output/event-phase6-20261023-real-compare/` 与其待审表逐条审核。
